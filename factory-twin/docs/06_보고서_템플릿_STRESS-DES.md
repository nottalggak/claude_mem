# 복제·개선 보고서 템플릿 (STRESS-DES 20항목 + VDI 3633-13 V&V 부록) — 근거 14

모든 트윈 보고서(v0.5 진단, v1 복제, 개선 권고)는 이 순서로 쓴다. 빠진 항목은 "해당 없음"이라도 적는다.

## A. 목적 (Objectives)
1. 목적: 어떤 결정을 위해 만들었나(병목·투자·레이아웃·인력·규칙).
2. 모델 출력: 보고하는 KPI 목록과 정의(주문/생산 리드타임 정의 포함).
3. 실험 목표: 비교할 시나리오와 수용 기준(P(개선) ≥ 0.9, p10 회수 ≤ 36개월 등).

## B. 논리 (Logic)
4. 베이스 모델 개요도(공정·버퍼·운반·외주 경로·투입 규칙).
5. 베이스 모델 논리: 배치 키, 디스패칭, 운반 트리거, 셋업 트리거, 고장, 휴식·잔업 캘린더.
6. 시나리오 논리: 각 시나리오가 바꾸는 것(패치 파일).
7. 알고리즘: 경로 탐색(A*), 묶음 창, 재작업 분기.
8. 구성요소: 엔티티(배치·재작업 묶음), 활동(공정), 자원(기계·운반자·대차·지게차), 큐(버퍼 용량), 진입·퇴출(주문 접수→상차).

## C. 데이터 (Data)
9. 출처: 방문·2주 로깅·기록(기간), 각 파라미터의 증인(R/S/O/E)과 신뢰 등급(A~D) — `tools/data_quality.py` 스코어카드 첨부.
10. 전처리: 기록 정규화(시각 복원 방법, imputed 표시), OCR 검증률, 이상치 처리, 야간 제외.
11. 입력 파라미터 표: 파라미터·명목값·출처·n·se·스크리닝 경계·조정 여부(≤ 검증 지표 수).
12. 가정: 모델링하지 않은 것(부재 식별 손실, 출하 용량 등)과 그 영향 방향.

## D. 실험 (Experimentation)
13. 초기화·워밍업: 초기 WIP(센서스), 워밍업 일수·방법.
14. 실행 길이·체제: 4주/체제, 체제 정의(성수기·비수기·믹스).
15. 추정 방법: 반복 수와 근거(CI 반폭 ≤ 5%), CRN 스트림 구성, 짝 비교·KN/OCBA.

## E. 구현 (Implementation)
16. 소프트웨어: SimPy 버전, 저장소 커밋 해시, 시나리오 파일명.
17. 난수: seed 집합, 주문/공정 스트림 분리.
18. 실행: 실행 시간, 하드웨어.

## F. 코드 접근
19. 모델·데이터 공유 범위(개인정보 제거본), 재현 명령(`run.sh`, `compare.py --seeds`).
20. 검증 결과 요약으로 연결(부록).

## 부록 V&V (VDI 3633-13 / Rabe–Wenzel 단계별)
- 데이터 검증: 질량 수지(재단=엣지=조립±불량, kWh=한전), 시계 정합, 커버리지(12개월 믹스의 ≥80%).
- 개념 모델 검토: 반장·사장과 벽 앞 워크스루 기록(날짜·참석·지적 사항).
- 구현 검증: 극한 조건 테스트(주문 0, 엣지밴더 정지), 트레이스·애니메이션 확인.
- 운영 타당성: §1.2 합격 표(v0.5/v1) 판정 결과, 홀드아웃 기간·지표, 튜링테스트 결과.
- 입력 불확실성: σ_I² 분해와 입력별 기여도, 결론 신뢰구간 표(`sim/out/uncertainty.md`).
- 민감도: 토네이도(상위 10개), 어떤 미검증 입력이 결론 부호를 바꾸는가.
- 적격 집합: 보정이 허용한 파라미터 범위(argmin 하나가 아님).
- 트윈 유지 시: 드리프트 지표(nRMSE 롤링, 리드타임 KS, 90% 예측 밴드 커버리지 ≈ 0.9, <0.8 지속 시 재보정).
