# 10. 맥미니(로컬)로 옮기기 — 클라우드 세션에서 로컬 Claude Code 로

이 저장소의 모든 산출물은 GitHub `nottalggak/claude_mem` 저장소의 **`factory-twin-research` 브랜치**, `factory-twin/` 폴더에 있다(클라우드 세션에서 작성한 파일은 전부 커밋·푸시됨 — 컨테이너에만 남은 것은 없다). 옮기는 것은 "복사"가 아니라 **클론**이다.

## 1. 한 번만 (맥미니 터미널)
```bash
# 1) 저장소 클론 (이미 있으면 git pull)
cd ~/Projects            # 원하는 상위 폴더
git clone https://github.com/nottalggak/claude_mem.git
cd claude_mem
git checkout factory-twin-research
cd factory-twin

# 2) 파이썬 환경 + 전체 테스트 체인 (python3 3.11+ 필요; 없으면 brew install python)
bash tools/setup_local.sh

# 3) 로컬 Claude Code 로 이 폴더를 연다 (플랜 사용량으로 과금 — 클라우드 세션 크레딧 아님)
claude            # 또는 Claude 데스크톱 앱에서 이 폴더를 프로젝트로 추가
```

## 3. 방문 후 48시간 작업 흐름 (로컬에서)
```bash
source .venv/bin/activate
python3 tools/templates_to_json.py capture/현장_채움본.xlsx data/공장A.json        # 시트 → factory.json (출처 자동, 가정 목록 출력)
python3 tools/test_converter.py data/공장A.json || true                           # (픽스처 전용 테스트 — 실제 공장엔 생략)
python3 sim/factory_sim.py data/공장A.json --name 공장A_base                       # 1회 실행
python3 sim/validate.py sim/out/공장A_base/kpis.json sim/out/공장A_base/factory.json   # §1.2 합격 판정
python3 tools/events_to_worklog.py ...     # 2주 양식(시트 13)을 worklog.csv/releases.csv 로 정리한 뒤 ↓
python3 tools/trace_validate.py data/공장A.json worklog.csv --releases releases.csv --level L0   # 구조 잔차 (L0 → L1)
python3 tools/rule_fit.py worklog.csv --releases releases.csv --factory data/공장A.json          # 규칙 재현율
python3 sim/sensitivity.py --factory data/공장A.json --seeds 3                                   # 재측정 우선순위
python3 tools/data_quality.py data/공장A.json sim/out/sensitivity.md                             # 출처 스코어카드
python3 sim/compare.py --factory data/공장A.json --seeds 5                                       # 시나리오 비교
python3 sim/uncertainty.py --factory data/공장A.json --B 20 --R 2                                # 결론 신뢰구간
```

## 4. 클라우드 세션 vs 로컬 — 과금과 역할
- **클라우드 세션**(claude.ai/code 의 원격 컨테이너)은 "클라우드 세션 크레딧"을 쓰고, 만료되면 플랜 사용량으로 넘어간다. 컨테이너는 휘발성이라 **커밋·푸시하지 않은 것은 사라진다**.
- **로컬 Claude Code**(맥미니 터미널 `claude` 또는 데스크톱 앱)는 플랜의 주간 한도(Max 20x)를 쓴다. 폴더·파일·브랜치를 직접 관리할 수 있고, 뷰어·시뮬레이션·엑셀을 바로 연다.
- 둘은 **같은 git 저장소**를 보므로 어느 쪽에서 작업해도 `git pull` / `git push` 로 이어진다. 이후 작업은 로컬에서 하고, 긴 배치 실행(불확실성 B=50 등)만 필요하면 클라우드로 보내는 식이 경제적이다.
- 로컬 Claude Code 세션은 이 저장소의 `CLAUDE.md`/`docs/00` 을 먼저 읽도록 "docs/00_종합보고서.md 와 docs/03_공장복제_명세서.md 를 읽고 시작" 이라고 첫 메시지에 적어 주면 맥락을 바로 잡는다.
