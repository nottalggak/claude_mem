# 공장 복제 명세서 — 무엇을 조사해서 어디에 넣으면 "정확한 복제"가 되는가

작성일 2026-10-10. 이 문서는 방문 당일 조사의 설계도다. 비주얼·엔진 구현은 다루지 않는다. 다루는 것은 세 가지뿐이다.
1. 복제가 "정확하다"는 말의 정의와 검증 방법
2. 복제에 필요한 데이터 요소 전체 목록, 각각을 어떻게·어느 정밀도로·누구에게서 얻는지
3. 그것을 하루 방문 + 2주 로깅 안에서 실제로 확보하는 워크플로우

---

## 1. 복제의 정의: 픽셀이 아니라 "행동"을 복제한다

공장을 복제한다는 것은 기계를 3D로 그리는 일이 아니다. **같은 주문을 넣었을 때 같은 출하·같은 재공·같은 대기·같은 동선·같은 전력이 나오는 모델**을 만드는 일이다. 그래서 복제의 정확도는 기하 정밀도가 아니라 **검증 지표의 일치도**로 정의한다.

### 1.1 복제 대상 5개 층
| 층 | 내용 | 틀리면 생기는 일 |
|---|---|---|
| ① 기하 | 벽·기둥·구역·기계 footprint·통로·버퍼 위치·출입구 | 동선 거리와 레이아웃 시나리오가 전부 틀림 |
| ② 자원 | 기계(능력·셋업·고장), 사람(스킬·배치·근무), 운반수단(대차·지게차·수량·속도), 공간(버퍼 용량) | 병목이 엉뚱한 곳에서 나옴 |
| ③ 흐름 | 제품별 실제 라우팅(재작업 루프·건너뛰기 포함), 주문 도착·믹스·배치 구성 규칙, 자재·정보 흐름 | 리드타임·WIP가 맞지 않음 |
| ④ 동역학 | 시간의 분포(평균이 아니라 min/mode/max), 변동 원인, 휴식·잔업·결근, 고장·자재 결품 | "평균 공장"은 실제보다 항상 빠르다(변동이 대기를 만든다) |
| ⑤ 의사결정 규칙 | 반장이 주문을 어떻게 묶고 순서를 정하는가, 어느 기계에 보내는가, 대차를 누가 언제 옮기는가, 셋업을 언제 하는가 | 규칙 없는 모델은 "이상적인 공장"을 그려서 개선 효과를 과대평가함 |

대부분의 실패는 ①②에만 집중하고 ④⑤를 놓쳐서 생긴다. **방문 시간의 절반은 ④⑤에 써야 한다.**

### 1.2 "정확하다"의 판정 기준 (검증 지표와 허용 오차)
복제본은 아래 지표를 같은 기간의 실제 기록과 비교해 허용 오차 안에 들어야 "복제됨"으로 선언한다.

| 검증 지표 | 실제 값의 출처 | 허용 오차(1차) | 어느 층을 검증하나 |
|---|---|---|---|
| 일/주 출하량 (제품별) | 출하일지, 작업일보 | ±10% | ②③ |
| 추적 배치의 리드타임(투입→출하) | 당일 **배치 추적**(§4.2) + 작업지시서 날짜 | ±15% | ③④⑤ |
| 시각별 구역 WIP(대차 수·부품 수) | 당일 **WIP 센서스**(§4.3) 2~3회 | ±20%, 순위 일치 | ③④ |
| 기계별 가동률 | CT 클램프 2주 로그 또는 영상 워크샘플링 | ±10%p | ②④ |
| 병목 기계 앞 평균 대기열 | WIP 센서스 + 영상 | 순위 일치, ±1대차 | ②④⑤ |
| 통로 게이트별 시간당 대차·지게차 통과 수 | 당일 **게이트 카운트**(§4.4) | ±20% | ①③ |
| 일 kWh, 최대수요 kW | 한전 고지서·파워플래너 15분 | ±10% / ±15% | ②(전력) |
| 셋업 횟수/일 | 반장 기록 또는 당일 관찰 | ±1회 | ⑤ |

허용 오차 안에 들지 않으면 §6의 보정 순서로 원인을 찾는다. **검증 없이 시나리오 결과를 내놓지 않는다.**

### 1.3 질문별로 필요한 정밀도가 다르다
| 우리가 답할 질문 | 결정적인 데이터 | 덜 중요한 데이터 |
|---|---|---|
| 병목이 어디인가 | 기계별 실효 사이클타임(핸들링 포함), 셋업 빈도·시간, 고장, 제품 믹스, 라우팅 | 기하 정밀도, 외관 |
| 어떤 기계를 사야 하나 | 병목 + 후보 기계의 실효 능력·가격·설치 공간·전력·집진 연결, 병목 이동 후 2차 병목 | 동선 |
| 레이아웃을 어떻게 바꾸나 | 흐름 from-to 행렬(배치가 어디서 어디로 몇 번), 대차 용량·속도, 통로 폭·기둥·집진 덕트·공압 배관·전기 트렌치(이동 불가 제약), 안전 통로 규정 | 기계 내부 구조 |
| 인력 배치를 어떻게 바꾸나 | 작업자별 스킬 매트릭스, 공정별 실제 인원과 역할, 대기·보행 비율(워크샘플링), 잔업 패턴, 외국인 비자 제약 | 기계 전력 |
| 동선을 어떻게 바꾸나 | 실제 이동 경로(영상/스파게티), 운반 트리거(누가 언제 왜 옮기나), 대차 수와 적재량, 빈 이동 비율 | 사이클타임 정밀도 |
| 전기요금을 어떻게 줄이나 | 기계별 상태별 kW, 집진기·컴프레서 운전 패턴, 15분 부하 곡선, 계약전력, 시간대별 요율 | 동선 |

→ 모든 것을 같은 정밀도로 재려 하지 말고, **질문별 결정적 데이터부터 확보**한다.

## 2. 데이터 요소 전체 목록 (복제에 필요한 것 / 수집 방법 / 정밀도 / 출처 / 함정)

### 2.1 ① 기하
| 요소 | 수집 방법 | 정밀도 | 출처(누가 아나) | 함정 |
|---|---|---|---|---|
| 공통 원점·좌표계 | 평면도 좌하단 기둥 모서리를 (0,0)으로 선언, 바닥에 테이프 표시, 모든 측정이 이 원점 기준 | — | 우리 | 각자 다른 원점으로 재면 합칠 수 없음 |
| 벽·기둥 그리드·문·출입구·하역장 | 건축물현황도 + 레이저 거리계(기둥 간격, 대각선 15개 이상) | ±2 cm | 도면, 소유자(세움터 발급) | 도면과 실물이 다름(증축·가벽) → 레이저로 검증 |
| 구역 경계(원자재·공정·조립·포장·완제품·사무·통로) | 평면도 위에 손으로 그리고 모서리 좌표 레이저 측정 | ±0.5 m | 반장 | 구역이 "문서상"과 "실제 쓰임"이 다름 — 실제 쓰임으로 |
| 기계 footprint(중심·L×W×H·방향) + 작업 공간(작업자 서는 곳, 판재 투입·배출 길이) | 레이저 또는 줄자, 사진, LiDAR 세그먼트 | ±5 cm | 현장 | 런닝쏘·엣지밴더는 기계보다 **판재 투입/배출 공간**이 더 크다 → 둘 다 기록 |
| 입력·출력 버퍼 위치와 **실제 용량**(대차 몇 대, 바닥 적치 몇 장) | 관찰, 사진, 반장 질문 "여기 최대 몇 대까지 두나" | 대차 1대 단위 | 반장 | 버퍼 용량이 블로킹을 결정한다. 과소평가 흔함 |
| 통로 폭, 기둥, 바닥 단차, 지게차/보행 분리 여부 | 레이저, 사진 | ±10 cm | 현장 | 통로가 재공으로 막혀 실제 폭이 다름 → "실효 폭" 기록 |
| 이동 불가 제약: 집진 덕트, 공압 배관, 전기 트렌치, 분전반, 도장 부스 배기, 건조실, 기초 앵커 | 사진, 설비담당 질문 | 위치 ±0.5 m | 설비/전기 담당 | 레이아웃 시나리오의 실현 가능성을 가름 |
| 랙·팔레트·대차·판재 번들 치수 | 줄자 | ±2 cm | 현장 | 재사용 에셋 |

### 2.2 ② 자원 — 기계
| 요소 | 수집 방법 | 정밀도 | 출처 | 함정 |
|---|---|---|---|---|
| 기계 ID·명칭·제조사·모델·연식 | 명판 사진 | — | 명판 | 명판 없으면 반장·구매 서류 |
| 공정 역할과 **처리 가능 제품/부품 범위**(최대 판 치수, 두께, 엣지 두께) | 반장 질문 | — | 반장 | "이 기계로 못 하는 것"이 라우팅 분기를 만든다 |
| 실효 사이클타임 = 기계 시간 + **핸들링**(올리기·정렬·뒤집기·내리기) | 스톱워치 10회(min/mode/max), 영상 | 초 | 관찰 | 기계 카탈로그 속도는 실효의 40~60%. 반드시 핸들링 포함 |
| 사이클타임의 **드라이버**(판 크기, 엣지 길이·변 수, 홀 수, 색상) | 측정 시 부품 치수 동시 기록 | — | 관찰 | 평균 1개 값으로 두면 믹스 변화를 반영 못 함 |
| 셋업: 종류(엣지 색·두께, 톱날, 보링 핀, 도장 색, 프로그램), 시간, **트리거 규칙**, 하루 횟수 | 관찰 1~2회 + 반장 질문 | 분 | 반장·작업자 | 셋업 시간보다 **빈도**가 더 큰 손실. 빈도는 작업일보로 |
| 고장·정지: 월간 횟수, 평균 수리 시간, 원인 | 설비 이력, 반장 기억("지난달 몇 번 섰나") | 회/월, 분 | 설비담당 | 하루 관찰로는 못 봄 → 기록·인터뷰 |
| 소정지(마이크로 스톱: 판 걸림, 테이프 끊김, 집진 막힘) | 영상 워크샘플링 | 비율 | 관찰 | 가동률 10~20%p를 먹는 숨은 손실 |
| 작업자 수(필수/보조)와 "사람 없으면 기계가 서는가" | 관찰 | 명 | 현장 | 2인 기계를 1인이 돌릴 때 사이클이 2배 |
| 불량·재작업 비율과 **재작업 경로**(어느 공정으로 되돌아가나) | 불량일지, 작업자 질문 | % | 품질 담당 | 재작업 루프가 라우팅에 빠지면 WIP가 안 맞음 |
| 전력: 명판 kW, 정지/공회전/가공 전류, 집진·공압 연결 | 명판, 클램프, 설비담당 | A | 전기안전관리자 입회 | 집진기·컴프레서가 20~50% |
| 공압 의존: 컴프레서 압력 부족 시 품질·속도 저하 여부 | 반장 질문 | — | 반장 | 숨은 공통 제약 |

### 2.3 ② 자원 — 사람
| 요소 | 수집 방법 | 함정 |
|---|---|---|
| 작업자 수, 공정별 **실제** 배치(공식 조직도와 다름), 이동 지원 패턴("바쁘면 누가 어디로 가나") | 반장 인터뷰 + 당일 관찰 | 조직도만 믿으면 안 됨 |
| 스킬 매트릭스(누가 어떤 기계를 혼자 돌릴 수 있나, 교육 기간) | 반장 작성(익명 번호) | 교차훈련 시나리오의 기반 |
| 근무: 시업·종업·휴식·점심·잔업 규칙·토요 특근 조건·결근율 | 인터뷰, 근태 기록 | 잔업이 "용량"의 숨은 버퍼 |
| 비자·고용형태 제약(E-9 비율, 체류 만료 예정) | 사장 | 인력 시나리오의 법적 제약 |
| 작업 중 시간 배분: 가공/핸들링/보행/대기/셋업/기타 | 워크샘플링(3분 간격 2시간, 전 작업자) | 가동률과 재배치 근거. 하루면 ±5~10% |
| 임금 수준(역할별, 추정) | 사장(범위로) | ROI 계산용. 개인별 아님 |

### 2.4 ② 자원 — 운반·공간
| 요소 | 수집 방법 | 함정 |
|---|---|---|
| 대차 종류·수량·적재량(부품 수/장 수)·누가 소유 | 세기, 사진 | 대차 부족이 병목인 공장이 많다 |
| 지게차 대수·운전자·속도·담당 구간·충전 | 관찰, 운전자 질문 | 지게차 1대가 원자재와 출하를 다 하면 양쪽이 서로 기다림 |
| 운반 **트리거 규칙**: 대차가 차면/반장이 부르면/정해진 시각에/작업자가 직접 | 작업자·반장 질문 + 관찰 | 모델의 운반 로직을 결정 |
| 적재·하역 시간, 빈 이동(빈 대차 회수) 비율 | 스톱워치, 영상 | 빈 이동이 전체의 절반 |
| 원자재 보관 방식(색상별 적층, 꺼내려면 재적재) 피킹 시간 | 관찰, 지게차 운전자 | 재단 앞 숨은 대기 |

### 2.5 ③ 흐름
| 요소 | 수집 방법 | 함정 |
|---|---|---|
| 제품군 4~8종과 **실제** 라우팅(도장 유무, 외주 구간, 재작업 루프, 건너뛰기) | BOM + 반장과 함께 제품별 흐름을 평면도에 그리기 | "표준 공정도"와 실제가 다름 |
| 부품 단위 속성(치수·엣지 변 수·홀 수·도장 여부) | BOM, 네스팅 출력물 | 사이클타임 드라이버 |
| 주문 도착: 일 주문 수, 제품 믹스, 수량 분포, 납기 길이, 계절성(입주 시즌) | 3~12개월 주문·출하 이력 | 하루 관찰로는 절대 못 잡음 → 기록 필수 |
| **배치 구성 규칙**: 주문 단위? 색상별 묶음? 하루치 묶음? 누가 결정? | 반장 인터뷰(가장 중요한 질문) | 배치가 리드타임·셋업·WIP를 지배 |
| 투입 규칙: 언제 재단을 시작하나(납기 역산? 자재 도착? 아침 일괄?) | 반장 | 투입이 많으면 WIP만 쌓임 |
| 우선순위 규칙: 급한 주문, 큰 고객, 색상 묶음 | 반장 | 시뮬의 디스패칭 규칙 |
| 키팅/분류: 한 주문의 부품이 여러 배치로 흩어져 마지막을 기다리나 | 조립 작업자 질문, WIP 관찰 | 조립 기아(starvation)의 원인 |
| 자재·부자재 결품 빈도(하드웨어·엣지테이프·포장재) | 구매담당·반장 | 대기 사유 중 큰 비중 |
| 외주 구간(도장 외주, 유리, 금속) 리드타임 | 사장 | 외부 지연이 내부 병목처럼 보임 |
| 정보 흐름: 작업지시서 전달 방식, 바코드 여부, 진척 확인 방법, 변경 통보 | 사무·반장 | 정보 지연 = 물리 지연 |
| 품질 검사 지점과 기준 | 관찰 | 검사가 숨은 공정 |

### 2.6 ④ 동역학(변동)
| 요소 | 수집 방법 |
|---|---|
| 각 시간의 분포: min/mode/max(삼각분포) 또는 평균·변동계수 | 스톱워치 10회 + 영상 재측정 |
| 하루 안의 리듬(아침 투입 몰림, 점심 후 재가동, 종업 전 정리) | 영상·게이트 카운트 시간대별 |
| 요일·월 패턴(월요일 투입, 월말 출하 몰림) | 작업일보 |
| 결근·지각, 기계 예열, 집진 청소 등 가용시간 손실 | 반장 |
| 고장·소정지·자재 결품의 빈도와 지속 | 기록 + 인터뷰 + 2주 CT 로그 |

### 2.7 ⑤ 의사결정 규칙 (인터뷰로만 얻어지는 것)
| 규칙 | 질문 방식 |
|---|---|
| 배치를 어떻게 묶나 | "오늘 재단할 걸 어떻게 정했어요? 종이 보여주세요" |
| 어느 기계로 보내나(엣지밴더 2대 중 선택) | "이건 왜 2호기로?" |
| 셋업을 언제 하나 | "색 바꾸는 걸 미루는 경우는?" |
| 운반을 누가 언제 | "대차는 누가 옮겨요? 언제?" |
| 잔업 결정 | "잔업은 어떻게 정해져요?" |
| 급한 주문 끼워넣기 | "급한 게 오면 어떻게?" |
| 조립 착수 조건 | "부품 다 안 왔는데 시작하나요?" |
| 품질 판정 | "이 정도 들뜸이면 다시 해요?" |
| 사람 돌리기 | "A가 쉬면 누가 대신?" |
규칙은 모델에 코드로 들어가야 하므로 **"만약 ~면 ~한다" 문장**으로 받아 적는다.

### 2.8 전력(별도 층)
명판 kW·상태별 전류, 집진기·컴프레서 운전 모드(상시/연동)와 카운터, 분전반 구성(어느 기계가 어느 회로), 변압기 kVA, 계약전력, 12개월 고지서(시간대별 kWh, 최대수요, 역률), 파워플래너 15분 데이터, 컴프레서 설정 압력·누설 여부, 집진기 댐퍼(수동/자동), 조명·난방.

## 3. 하루 방문으로 잡을 수 있는 것과 없는 것

| 하루에 잡힘 | 하루로는 불가 → 대체 수단 |
|---|---|
| 기하, 기계 사양, 사이클타임 모드값, 운반 경로, 규칙(인터뷰), WIP 스냅샷, 게이트 카운트, 전력 스팟 측정 | **변동과 희귀 사건**(고장, 결품, 결근) → 설비이력·작업일보·2주 CT 로그 |
| | **주문 패턴·계절성** → 3~12개월 주문·출하 이력 |
| | **진짜 가동률** → 2주 CT 클램프(기계 상태) + 카메라 |
| | **규칙의 예외**(급한 주문, 고객별) → 반장과 2차 통화, 작업지시서 샘플 30장 |
| | **방문일 편향**(보여주기, 평소와 다른 날) → "오늘이 평소와 어떻게 다른가" 질문, 기록으로 교차 |

결론: **방문 1회 + 기록 수령 + 2주 비침습 로깅(CT 클램프 3~5대, 카메라 2~3대) + 2차 방문(검증)**이 최소 구성이다. 2차 방문은 모델이 틀린 곳을 알고 가는 방문이라 1차보다 짧다.

## 4. 방문 당일 워크플로우 (조사가 복제로 이어지도록 설계)

## 5. 수집 데이터 → 모델 매핑 (무엇이 어디로 들어가나)

| 수집물 | 모델 요소(`factory.json`) | 변환 규칙 |
|---|---|---|
| 평면도·레이저·LiDAR | `site.zones`, `site.obstacles`, `stations[].pos/size`, 통로 | 공통 원점 좌표로 변환, 이동 불가 제약은 `obstacles`에 유형 태그 |
| 기계대장·명판·클램프 | `stations[]` 사양, `rated_kw/load_factor/idle_kw`, `ancillary` | kW = √3·V·A·PF/1000, 부하율 = 가공 kW / 정격 |
| 시간연구(min/mode/max + 부품 치수) | `cycle.base_min`, `per_unit`(면적·엣지 m·홀 수 계수), `cv` | 회귀: 시간 = a + b·엣지m + c·홀수; 핸들링은 `base_min` |
| 셋업 관찰 + 작업일보 빈도 | `setup_min`, 셋업 트리거 규칙 | 트리거를 제품 속성(색·두께)으로 정의 |
| 설비 이력 | `mtbf_min/mttr_min` | 월 횟수 → 가동분/횟수 |
| 불량일지 + 재작업 경로 | `scrap_rate`, 라우팅의 재작업 루프 | 루프는 `routing`에 확률 분기 |
| 버퍼 관찰 | `buffer_batches`, `in_pos/out_pos` | 대차 수 단위 |
| 대차·지게차·운반 규칙 | `transport` + 운반 트리거 규칙 | 트리거를 코드 규칙으로 |
| 스킬 매트릭스·근무·잔업 | `workers[]`, `meta.shift`, 잔업 규칙 | 잔업은 용량 시나리오 |
| BOM·네스팅 | `products[].parts`, `routing` | 부품 속성이 사이클 드라이버 |
| 주문·출하 이력 | `orders`(도착률·믹스·배치 규칙·납기) | 요일·월 패턴 유지, `mode: list`로 실제 이력 재생 가능 |
| 배치 추적·센서스·게이트 카운트·고지서 | `observations` (검증 전용, 모델 입력 아님) | §1.2 검증 지표로만 사용 |

원칙: **관측치 중 일부는 입력이 아니라 검증에만 쓴다.** 같은 데이터로 맞추고 같은 데이터로 검증하면 복제가 아니라 끼워맞춤이다.

## 6. 보정·검증 절차 (틀렸을 때 어디부터 고치나)

1. **구조 확인**: 라우팅·기계 수·작업자 배치·버퍼 용량이 관찰과 같은가. (틀리면 시간 보정은 의미 없음)
2. **결정적 시간 확인**: 사이클·셋업·운반 시간 모드값으로 돌려 배치 추적 리드타임의 "최솟값"이 맞는가.
3. **변동 추가**: 분포·고장·결품을 넣어 WIP 센서스와 대기열이 맞는가. (안 맞으면 변동이 부족하거나 규칙이 틀림)
4. **규칙 확인**: 배치 구성·투입·우선순위·운반 트리거를 반장 규칙으로 바꿔 셋업 횟수·WIP 분포가 맞는가.
5. **민감도 분석**: 각 파라미터를 ±20% 흔들어 출하·리드타임이 가장 크게 움직이는 상위 10개를 뽑는다 → **이 10개를 2주 로깅·2차 방문에서 다시 잰다.** 나머지는 추정으로 둬도 된다.
6. **외부 검증**: 모델이 보지 않은 주(週)의 출하량·고지서 kWh를 맞추는가.
7. 통과하면 "복제 v1 검증됨" 선언과 함께 **불확실 파라미터 목록과 그 영향 범위**를 보고서에 명시한다. 이 목록이 없는 복제는 신뢰할 수 없다.

## 7. 복제를 망치는 흔한 실수 10가지
1. 기계 카탈로그 속도를 사이클타임으로 씀(핸들링 누락)
2. 셋업 시간만 재고 **빈도**를 안 잼
3. "표준 공정도"를 라우팅으로 씀(재작업·건너뛰기·외주 누락)
4. 제품을 평균 1종으로 뭉갬(믹스 변화 반영 불가)
5. 배치 구성·투입 규칙을 안 물어봄(모델이 이상 공장이 됨)
6. 버퍼 용량을 무한으로 둠(블로킹 사라짐)
7. 운반을 순간이동으로 둠(대차·지게차 경합 사라짐)
8. 하루 관찰로 고장·결품을 0으로 둠
9. 집진기·컴프레서를 전력에서 빼놓음
10. 입력에 쓴 데이터로 검증함

## 8. "완벽하게 바꾸기"로 이어지는 순서
복제가 검증된 뒤에만 개선으로 넘어간다. 순서는 제약이론 5단계를 따른다.
1. 병목 식별(가동률·대기·블로킹·센서스 일치로 확정)
2. 병목을 **투자 없이** 100% 쓰기: 셋업 줄이기, 휴식 교대, 병목 앞 버퍼 확보, 불량품 병목 투입 금지
3. 나머지를 병목에 종속: 투입을 병목 속도에 묶기(과잉 재단 금지), 배치 크기 조정
4. 병목 능력 증설: 2호기·자동화·리턴컨베이어 → 시뮬로 2차 병목 위치와 회수기간 확인
5. 새 병목으로 반복
레이아웃·인력·동선은 각 단계에서 시나리오로 평가하며, 인력은 재배치·교육·채용 우선순위로만 표현한다.

## 10. 검증 실험으로 확인된 사실 (2026-10-10, 샘플 공장 라운드트립·민감도)

### 10.1 공장 기록만으로 무엇이 복원되는가 — 라운드트립 실험
시뮬레이션이 만든 5일치 이벤트를 공장 작업일보 형태(배치·제품·부품수·공정·도착·착수·완료)로 바꾼 뒤 `tools/log_to_model.py`로 역추정해 원래 파라미터와 비교했다.
| 복원 대상 | 결과 | 의미 |
|---|---|---|
| 라우팅 변형·from-to 행렬 | 완전 복원 | 배치 ID와 공정명만 있으면 된다 |
| 공정별 대기시간 | 모델값과 ±5% 일치 (예: CUT2 134 vs 130분, EB2 151 vs 145분) | **도착 시각**이 기록에 있어야 한다 |
| 공정별 가공시간(부품당) | 복원 | **착수 시각**이 있어야 한다. 완료 시각만 있으면 대기+운반이 섞여 분리 불가 |
| 셋업 시간 | 제품 전환 표본이 10개 이상인 공정만 ±0~1분, 그 외 크게 틀림(건조실 42분 추정 vs 실제 0) | 셋업은 역추정하지 말고 **직접 기록**(시트 5) |
| Little's law WIP | 12.1 vs 모델 13.3 | 기록 기반 리드타임×처리량이 센서스와 맞는지로 기록 누락을 탐지할 수 있다 |
| 고장·결품·작업자 가동 | 불가 | 작업 기록엔 없다 → 설비이력·CT 로그·워크샘플링 |

→ **공장에 요청할 기록의 최소 형식**: 배치(주문)번호, 제품, 수량/부품 수, 공정, 대차 도착 시각, 착수 시각, 완료 시각. 바코드가 있으면 "도착·착수·완료 3회 스캔", 없으면 2주간 종이 양식(시트 13 형식)으로 반장이 기록. 완료 시각만 적는 기존 작업일보는 라우팅과 출하량 검증에만 쓴다.

### 10.2 어떤 파라미터가 결론을 흔드는가 — 민감도 스크리닝
`sim/sensitivity.py`로 주요 파라미터를 ±20% 흔든 결과(샘플 공장):
- **배치 크기 규칙**이 압도적 1위(리드타임 변동폭 52%p, 처리량 12%p). 이것은 기계 사양이 아니라 **반장의 의사결정 규칙(⑤층)**이다. 기계를 아무리 정밀하게 재도 배치 규칙을 틀리면 복제가 아니다.
- 그다음이 병목 후보 기계들의 **실효 가공시간**(EB2, CUT1/2, 조립 벤치)과 **셋업**. 운반 속도·버퍼 용량은 이 샘플에선 하위.
- 병목의 정체(CUT2 ↔ EB2)가 ±20% 안에서 뒤바뀐다 → 두 기계의 실효 사이클을 ±10% 이내로 재야 "병목이 어디다"를 말할 수 있다. 이것이 시간연구 표본 수를 정하는 근거다.
- 절차: 1차 모델 → 민감도 상위 10개 → 그것만 2주 로깅·2차 방문에서 재측정 → `tools/data_quality.py`로 "상위 10개 중 아직 추정인 것"이 0이 될 때까지.

### 10.3 데이터 출처 태깅
`factory.json`에 `provenance` 블록으로 파라미터별 출처(measured/record/interview/estimated)를 남긴다. 스코어카드(`tools/data_quality.py`)가 민감도 상위 파라미터가 추정에 머물러 있으면 경고한다. **복제 보고서에는 이 스코어카드를 반드시 첨부한다.**
