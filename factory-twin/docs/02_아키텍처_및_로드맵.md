# 디지털 트윈 아키텍처 및 로드맵

## 1. 설계 원칙
1. **단일 진실 원천은 `factory.json`** (`schema/factory.schema.json`). 평면도·기계·작업자·제품·주문·관측치가 모두 여기 들어가고, 시뮬레이션·3D 뷰어·(나중에) OpenUSD 내보내기가 전부 이 파일에서 생성된다.
2. **2.5D 파라메트릭 모델 우선, 포토리얼은 레이어로.** 기계는 L×W×H 박스 + 사진/저폴리 스탠드인, 바닥·구역은 폴리곤. 스캔 포인트클라우드는 "위에 대고 그리는 참고 이미지", 가우시안 스플랫은 토글 가능한 시각 배경. 자동 3D 인스턴스 분할(Mask3D 등)은 공장 스캔에 신뢰도가 낮아 쓰지 않는다.
3. **시뮬레이션과 뷰어는 이벤트 로그(JSONL)로만 통신.** 뷰어는 시뮬레이션을 모른다. 라이브 IoT 단계에서는 같은 포맷을 MQTT로 흘린다.
4. **상용 DES 도구 없이** SimPy 엔진을 소유한다(라이선스 0원, 공장마다 템플릿 재사용). 검증은 FlexSim Express/Plant Simulation 학생판으로 교차 확인만(상업 사용 불가).

## 2. 구성 요소 (현재 저장소)

```
factory-twin/
  schema/factory.schema.json      데이터 모델
  data/build_sample.py            샘플 공장(가상) 생성기 → sample_factory.json
  capture/templates/*.xlsx        현장 수집 템플릿 (12 시트)
  tools/templates_to_json.py      xlsx → factory.json
  sim/pathfind.py                 격자 A* (기계·기둥 회피, 동선 거리)
  sim/factory_sim.py              SimPy DES: 주문→배치→공정, 버퍼 블로킹, 셋업, 고장, 휴식, 운반, 에너지
  sim/compare.py                  시나리오 일괄 실행(seed 반복), 비교표, 연간 효과·회수기간
  scenarios/*.json                what-if 패치(설비 추가, 배치 크기, 레이아웃, SMED, 교체)
  viewer/index.html               Three.js 뷰어: 3D/평면, 타임라인 재생, 상태 색, 대기열, 히트맵, 스파게티, KPI
  docs/                           보고서·체크리스트·리서치 원문
```

### 2.1 시뮬레이션 모델 (sim/factory_sim.py)
- 엔티티: 주문(배치) = 제품 N개분 부품 묶음. `products[].routing` 순서로 공정을 거친다.
- 스테이션: `capacity`(기계 대수), 입력 버퍼(`buffer_batches`, 초과 시 상류 **블로킹**), 셋업(제품 전환 시), 고장(MTBF/MTTR 지수분포), 불량률(재가공), 처리시간 = `base + Σ per_unit × 부품속성`(판 면적·엣지 길이·홀 수) 또는 제품별 고정시간, 변동계수(lognormal).
- 운반: 운반 인원(대차)·지게차를 자원으로 공유. 격자 A* 경로 길이/속도 = 이동 시간 + 적재·하역. 빈 이동도 기록 → 스파게티·히트맵.
- 근무: 교대·휴식 시간에는 가공·운반 중단(야간 넘김).
- 에너지: 기계 상태별 kW(가동 = 정격×부하율, 대기 = 대기전력) + 부대설비(집진기: 연결 기계 가동 시, 컴프레서: 근무시간) + 기본부하 → kWh, 전기요금.
- 출력: `events.jsonl`, `kpis.json`(가동률·대기·WIP·리드타임·운반거리·전력·병목 순위), `factory.json`(시나리오 적용본).
- 병목 점수 = 0.6×가동률 + 0.4×정규화 평균 대기. (Roser의 active-period 방법으로 고도화 가능.)
- 주문 스트림과 공정 변동은 **별도 난수 스트림**이라 시나리오 간 동일 주문으로 공정하게 비교된다.

### 2.2 뷰어 (viewer/index.html)
- Three.js r170 로컬 번들(CDN 불필요). 좌표: 데이터 (x, y) → three (x, 높이, −y).
- 구역 폴리곤, 기둥, 벽, 기계 박스(상태 색: 가동/대기/셋업/고장), 입력 버퍼 대기 스택, 운반자/지게차 애니메이션(경로 보간), 통행 히트맵(0.5 m 격자), 스파게티 라인, 라벨, KPI 패널, 시나리오 선택, 타임라인(야간 자동 스킵), 기계 클릭 상세.
- 다음 단계: React Three Fiber 이관 시 WareTwin(MIT) 구조 참고, 스플랫 배경은 Spark(`@sparkjsdev/spark`) `SplatMesh`, 기계 GLB는 gltf-transform 최적화.

### 2.3 시뮬레이션 ↔ 뷰어 계약 (events.jsonl)
```jsonl
{"type":"release","batch":"B001","product":"P_DESK","qty":10,"n_parts":80,"t":480.0}
{"type":"move","vehicle":"H1","batch":"B001","path":[[10.5,19],[13.5,25.5]],"duration":0.6,"loaded":true,"parts":80,"t":481.5}
{"type":"queue","station":"CUT1","len":1,"t":482.1}
{"type":"state","station":"CUT1","state":"busy","t":482.1}
{"type":"proc_end","station":"CUT1","batch":"B001","duration":41.3,"t":523.4}
```
단위: 분(시뮬레이션 시작 = Day 1 00:00), 좌표 m. 라이브 단계에서는 `t`를 epoch 초로 바꾸고 같은 스키마를 MQTT 토픽 `kr/<site>/<area>/<machine>/state`로 발행.

## 3. 캡처 → 모델 파이프라인
1. **현장**: Scaniverse LiDAR 세그먼트(LAS/GLB/SPZ) + 레이저 제어 치수 + 360 영상 + 명판 사진 + 템플릿 xlsx.
2. **정합**: CloudCompare로 세그먼트를 제어점(기둥 모서리)에 정합 → 평면 래스터. 기대 정확도 ±5~15 cm.
3. **기계 추출**: Open3D `segment_plane`(바닥) → DBSCAN 블롭 → OBB(L×W×H, yaw) 자동 제안 → 사람이 기계대장과 대조·수정(pystruct3d 참고).
4. **명판**: VLM(JSON 스키마 강제) + PaddleOCR 교차 → 사람 검토 → 기계대장. 치수는 VLM 추정 대신 A4/팔레트 기준물 호모그래피 또는 iPhone 측정.
5. **동선**: 고정 카메라 영상 → YOLO11 + ByteTrack(BoxMOT) → 바닥 호모그래피 → (x, y, t, id) → 히트맵·스파게티(`observations.spaghetti`). AGPL 회피가 필요하면 Apache 검출기 + 자체 트래커.
6. **전력**: 명판 kW × 측정 부하율 × 가동시간; 2주 Shelly Pro 3EM 로깅으로 보정; 한전 파워플래너 15분 데이터로 피크 검증.
7. **변환**: `tools/templates_to_json.py` → `factory.json` → `sim/compare.py` → 뷰어.

## 5. 알려진 한계·주의
- 샘플 공장의 모든 수치는 **가상 추정치**. 현장 측정으로 교체하기 전엔 절대치를 보고서에 쓰지 말 것.
- 조립/포장은 "배치 = 1 벤치"로 단순화. 실제로는 여러 명이 한 배치를 나눠 조립하므로 `capacity`·`per_product`로 보정.
- 집진기 가동시간은 연결 기계 가동시간의 근사(×1.3, 근무시간 상한). 실측 로깅으로 교체.
- 인력 조정 제안은 근로기준법 제23·24조, 개인정보보호법, AI기본법(2026-01 시행)의 제약을 받는다. 개인 식별 데이터는 수집·사용하지 않고 공정·역할 단위로만 집계한다.
