## 1. Input data modeling (입력 데이터 모델링)

### 1.1 How many cycles per activity time?

**Formula (Niebel & Freivalds; NCEES FE reference).** For a relative precision *k* (e.g., 0.05) at confidence *z*:

  n = ( z · s / (k · x̄) )²  → round up; for a pilot of n′ < 30 cycles replace z with t(n′−1).

z = 1.645 / 1.960 / 2.576 for 90 / 95 / 99 %. Worked example in circulation: x̄ = 0.361 min, s = 0.03, k = 0.05, z = 1.96 → n = (1.96·0.03/(0.05·0.361))² = 10.6 → **11 cycles**; Niebel's own t-based example gives 21 for 9 d.f. (t = 2.262). Sources: [open-exam-prep FE guide](https://open-exam-prep.com/study-guides/fe-industrial/work-design-measurement/time-study-standard-times), [Scribd worked example](https://www.scribd.com/document/475010410/Time-Study), [Hadad, Keren & Hanani 2014, EJIE 8(2) — two alternative methods for #cycles](https://ideas.repec.org/a/ids/eujine/v8y2014i2p222-243.html).

**General Electric guideline (Niebel & Freivalds, Table "Recommended number of cycles") [textbook/recall]:** cycle 0.10 min → 200; 0.25 → 100; 0.50 → 60; 0.75 → 40; 1.0 → 30; 2.0 → 20; 2–5 → 15; 5–10 → 10; 10–20 → 8; 20–40 → 5; > 40 min → 3. ILO *Introduction to Work Study* practice: when several operators do the same job, run **short studies of 10–15 cycles on each operator** rather than one long study ([Scribd/ILO-derived notes](https://www.scribd.com/document/926204178/Methods-Engineering-Time-Study)).

**Applied to this plant (est.):** edge bander per panel (0.3–1 min) → 40–60 cycles per part family; CNC boring (0.5–2 min) → 20–30; beam saw/nesting per program (5–15 min) → 8–10 programs; assembly (10–30 min/unit) → 5–8 units per product family; packing (3–8 min) → 10–15. One observation day cannot deliver these counts for every family — hence machines are covered by the 2-week CT/camera log (hundreds of cycles), and the day is reserved for manual elements and for *calibrating the rating factor* (performance rating 평정).

**Variance-based rule (CV):** since n ∝ (CV/k)², a CV of 0.15 at 95 %/±5 % needs 35 cycles; CV 0.30 needs 138. Compute CV from the first 10 cycles and re-plan.

### 1.2 Work sampling (워크샘플링) sample size

  n = z² · p(1−p) / e²  (e = absolute error in proportion units). ILO shorthand n = 4p(1−p)/L² (z² ≈ 4 ⇒ 95 %).
Sources: [ILO-derived Scribd notes](https://www.scribd.com/presentation/18479539/Work-Sampling2), [Wikipedia Work sampling](https://wikipedia.com/wiki/Work_sampling), [machine-downtime example](https://www.scribd.com/doc/249857515/Chapter-12-Work-Sampling).

**Worked example, 90 % confidence, ±5 % absolute, p unknown (use 0.5):** n = 1.645² × 0.25 / 0.05² = 2.706 × 0.25 / 0.0025 = **271 observations**. If the pilot shows idle fraction p = 0.30: n = 2.706 × 0.21 / 0.0025 = **228**. If you want ±5 % *relative* on p = 0.30 (e = 0.015): n = 2.706 × 0.21 / 0.000225 = **2,526** — only feasible from the 2-week camera record, not from one day. Practical: 271 observations / 20 workers ≈ 14 randomized tours of the floor in one day (one every ~35 min), which is doable; but do the per-state split (working / handling / waiting / absent) from camera frames sampled at random times over 10 working days.

### 1.3 Choosing distributions with few samples

- Law's input-modeling tutorial: with data, (a) fit a theoretical distribution, (b) else use an empirical distribution; with **no data**, use **triangular** (min/mode/max from experts) or beta; goodness-of-fit conclusions are unreliable for small samples and histograms become ragged ([Law, WSC 2012 tutorial](https://www.informs-sim.org/wsc12papers/includes/files/inv225.pdf); [Kuhl et al., WSC 2006](https://simulation.tudelft.nl/SEN9110/termpapers/input/KuhlEtAl_WSC2006_Introduction%20to%20Modeling%20and%20Generating%20Probabilistic%20Input%20Processes%20for%20Simulation.pdf); [Nottingham lecture](https://www.cs.nott.ac.uk/~pszps/asss2014/resources/ASSS-Lec15_2014.pdf)).
- Trace vs fitted: theoretical distributions smooth out irregularities and can generate values outside the observed range (useful for stress tests) ([WSC input-analysis slides](https://www.slideshare.net/slideshow/input-analysis/148921822)).
- Lognormal for human task times is supported mainly by general response-time literature (right-skew, variance grows with mean) ([Dix HCI stats](https://alandix.com/glossary/hcistats/log-normal%20distribution)); two assembly studies assumed **normal** ([arXiv 2007.01921](https://arxiv.org/pdf/2007.01921); [IJPE 2008](https://ideas.repec.org/a/eee/proeco/v114y2008i1p239-251.html)). → Do not assume; test lognormal vs gamma vs normal on your own 2-week data.

**Decision rule for this project (est., consistent with Law):**
| n available | Use |
|---|---|
| 0–9 | Triangular(min, mode, max) from PMTS estimate ± expert; or lognormal with CV fixed at 0.2–0.3 from similar elements |
| 10–30 | MLE fit of lognormal/gamma; judge with Q–Q plot, not KS p-value |
| > 30 (logged machine cycles) | Fit + Anderson–Darling; fall back to empirical CDF if no fit; keep tail (> P95) empirical |
| Machine-paced (edge bander feed, CNC program) | Deterministic program time + small lognormal noise; **separate handling time** (load/unload, manual) from machine time — handling is where variance and the operator rating live |

**Setup frequency from logs:** derive from ERP/MES order-change events: setup count = number of adjacent production records on the same machine with a different item/program; setup duration = gap between last completion of lot i and first completion of lot i+1 minus the first-piece cycle time (the start-time repair logic of §4). Report "setups per shift" as a rate and fit the gap as lognormal; validate against the observation-day stopwatch of 3–5 real changeovers.

### 1.4 PMTS (MTM / MOST) to *estimate* manual handling without measuring everything

- Units: 1 TMU = 0.036 s = 0.0006 min; 100,000 TMU = 1 h ([MTM explainer](https://www.sugoyaindia.com/?p=3328)).
- **MOST** sequence model for General Move: A B G A B P A (Action distance, Body motion, Gain control, Placement); index scale 0,1,3,6,10,16,24,32,42,54; time = Σindex × 10 TMU; e.g., A0B0G0 A1B0P1 A0 = 20 TMU ([KSU IE342 lab handout, free](https://fac.ksu.edu.sa/sites/default/files/ie342_lab-5_most.pdf); [SlideShare MOST](https://www.slideshare.net/SohitChauhan1/most-maynard-operation-sequence-technique)). BasicMOST applies to cycles of ~ seconds to 10 min ([Wikipedia MOST](https://en.wikipedia.org/wiki/Maynard_operation_sequence_technique)).
- **Accuracy claims:** MOST values "within ±5 % of true time at 95 % confidence" is the vendor claim, repeated in secondary sources ([US patent 7,149,700](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/7149700); [SlideServe](https://www.slideserve.com/neka/most)). The MTM-HWD validation (62 German workplaces) confirms a ±5 % envelope relative to MTM-1 ([Faber et al. 2019, TH-OWL](https://www.th-owl.de/elsa/record/10656)). A widely copied comparison table gives per-100-TMU error of MTM-1 ±21 %, MTM-2 ±40 %, MTM-3 ±7 % with analysis effort 250×/100×/35× cycle time — ambiguous wording, so treat only as "accuracy improves with cycle length; ±5 % holds for ≥ ~1,000 TMU (36 s) blocks" **[est.]** ([OnlineClothingStudy](https://www.onlineclothingstudy.com/2013/12/comparison-of-mtm-1-mtm-2-and-mtm-3.html)). IMEKO 2020: MTM more precise, BasicMOST faster to apply ([IMEKO TC10-2020-058](https://imeko.info/publications/tc10-2020/IMEKO-TC10-2020-058.pdf)); a refrigerator-door case found MOST closer to stopwatch than MTM-1 ([Bureš & Pivodová, IEEM 2013](https://publikace.k.utb.cz/handle/10563/1003962)).
- **Free data cards:** official MTM-1 data card EN PDF ([mtm.org](https://mtm.org/fileadmin/user_upload/MTM-1_datacard_2019_EN.pdf)), DE version ([mtm.org](https://mtm.org/fileadmin/user_upload/MTM-1_Datenkarte_DE.pdf)), MTM-UAS basic-operation card (CZ) ([mtm.org](https://mtm.org/fileadmin/user_upload/MTM-UAS_data_card_A5_basic_operation_2019_CZ_2026.pdf)); the MTM Association warns that uncertified use yields wrong results. University lecture notes with the MTM-1 tables: [EMU IENG301 Ch.28](https://staff.emu.edu.tr/orhankorhan/Documents/courses/ieng301-mane301/Lecture-Notes/spring2019-2020/CH28.pdf). BasicMOST cards are proprietary (Zandin, *MOST Work Measurement Systems*, CRC) — the KSU handout above has enough of the General Move table for panel handling.
- **Use in this project:** PMTS gives *normal-pace* times for panel pick/turn/place at edge bander, stacking, dowel insertion, carton closing; multiply by an allowance factor (ILO typical 10–15 %) **[textbook]** and use the stopwatch day only to confirm the ratio (observed/PMTS) per station. Panel handling of 18 mm MFC panels > 1.2 m typically runs 150–400 TMU per get/put (5–15 s) **[est.]**.

## 2. Verification & validation (검증·타당성 확인)

### 2.1 Frameworks

- **Sargent** (WSC 1996–2005, 2016 tutorial; *J. Simulation* 7(1):12–24, 2013, doi 10.1057/jos.2012.20): conceptual-model validity, computerized-model verification, operational validity, data validity; techniques: animation, comparison to other models, degenerate tests, event validity, extreme-condition tests, face validity, historical data validation, internal validity (replication variance), multistage validation, operational graphics, parameter variability/sensitivity, predictive validation, traces, **Turing tests**; statistical approaches for observable systems: hypothesis tests, confidence intervals, graphical comparison, with the "acceptable range of accuracy" set *before* testing and Type I/II risks (model builder's/user's risk) stated ([Sargent 2013](https://ideas.repec.org/a/taf/tjsmxx/v7y2013i1p12-24.html); [Sargent, Goldsman & Yaacoub WSC 2016](https://www.informs-sim.org/wsc16papers/016.pdf); [open PDF of tutorial](https://ics.uu.nl/docs/vakken/msosi/VerificationValidationSargent.pdf)).
- **Balci**: 77 V&V techniques in four classes — informal (audits, walkthroughs), static, dynamic, formal — WSC 1998 ([Balci WSC 1998](https://www.informs-sim.org/wsc98papers/006.PDF); [Balci slides](https://sigsim.acm.org/mskr/Courseware/Balci/Slides/BalciSlides-21-VVTechniques.pdf)).
- **Law's 7-step approach** (WSC 2003→2022; "10 steps" in 2025): definitive problem formulation; SME interviews; regular contact with decision-maker; **written assumptions document** with structured walk-through; validity check of conceptual model; programmed-model verification; **comparison of model and system output for the existing system**; sensitivity analysis to find important factors; results validation. Law stresses validity ≠ credibility ([Law WSC 2022](https://www.informs-sim.org/wsc22papers/128.pdf); [Law WSC 2003](https://www.informs-sim.org/wsc03papers/009.pdf); [Law WSC 2025](https://www.informs-sim.org/wsc25papers/inv124.pdf)).
- **Production/logistics-specific**: Rabe, Spieckermann & Wenzel's V&V procedure model attaches V&V activities and documents to *each phase* of the simulation study (task definition → system analysis → model formalization → implementation → experiments) ([WSC 2008 pp.1717–1726](https://www.simplan.de/wp-content/uploads/2008_WinterSim_EN.pdf); [SNE 19(2) 2009](https://www.sne-journal.org/fileadmin/user_upload_sne/SNE_Issues_OA/SNE_19_2/articles/sne.19.2.09935.tn.OA.pdf)). **VDI 3633 Blatt 13** "Verification and validation" (draft Feb 2023) covers V&V of data, models and results from data acquisition through experiment design ([VDI](https://vdi.de/en/home/vdi-standards/details/vdi-3633-blatt-13-simulation-of-systems-in-materials-handling-logistics-and-production-verification-and-validation)).

### 2.2 Operational validation techniques for this factory

1. **Trace-driven / historical replay**: feed the actual 3–12-month order list into the model and compare daily output, lead time, WIP. Note the statistical trap: trace-driven runs make real and simulated outputs cross-correlated, so paired comparison is required ([WSC 2000 trace-driven validation](https://www.informs-sim.org/wsc00papers/116.PDF)). **Kleijnen, Bettonvil & Van Groenendaal (1998)** give the formal test: regress (real − sim) on (real + sim) and test intercept = 0 and slope = 0 ([Management Science 44(6):812–819](https://ideas.repec.org/a/inm/ormnsc/v44y1998i6p812-819.html)) — this is the single most appropriate test for a record-driven twin.
2. **Kleijnen 1995**: three data situations — no data, output only, input+output — with two-sample t on means for output-only ([EJOR 87(1):21–34](https://ideas.repec.org/a/eee/ejores/v87y1995i1p21-34.html)).
3. **Hypothesis tests / CI on means**: paired t on daily throughput (sim vs real for matched days); report the CI on the difference and judge against a pre-set practical tolerance rather than p-values alone (Law). A packaging-line case used α = 0.05 against log-book output ([UMP JMMST](https://journal.ump.edu.my/jmmst/article/download/6083/1281)).
4. **Schruben–Turing test**: present plant managers with unlabeled real and simulated daily reports (output per station, WIP snapshots, Gantt); if they cannot identify the simulated ones better than chance, face validity is established (Schruben 1980, *Simulation* 34(3):101–105 **[recall]**; cited as "Schruben–Turing tests" in [EJOR 1995 review](https://ftp.iaorifors.com/paper/21697)).
5. **Event validity & extreme-condition tests**: zero orders → zero output; edge bander down 100 % → downstream starvation pattern; these are cheap and catch logic errors.

### 2.3 Acceptance tolerances

No published norm was found. Observed practice: one plant-expansion study required **±1 % annual throughput** ([WSC 1997 case](https://www.informs-sim.org/wsc97papers/0744.PDF)); a patent on factory modeling matches throughput, cycle time and WIP means *and variances* without a number ([US 5,140,537](https://patents.google.com/patent/US5140537)); a 2025 engineering review grades fidelity by percent deviation of outputs ([ScienceDirect 2025](https://www.sciencedirect.com/science/article/pii/S2667305325000420)). **Recommended for this project [est., consistent with common consulting practice]:** throughput (units/day, weekly) within **±5 %** and the sim 95 % CI must cover the real mean; order lead time **±10 %** on mean and P90; WIP/buffer levels **±15 %**; station utilization **±5 percentage points**; the Turing test ≥ 50 % misclassification. Set them in the assumptions document *before* the first comparison (Sargent).

**Calibration vs validation split:** fit/calibrate on the first ~2/3 of the production records and the 2-week log; hold out the last 1/3 (or a different season/product-mix period) for validation; the holdout should "challenge" the model — pick a period with a different mix, not the easiest month ([data-splitting evidence](https://scholarsarchive.byu.edu/iemssconference/2018/Stream-F/34); [arXiv 1108.6043](https://pdf.arxiv.org/pdf/1108.6043)). Never tune a parameter on the holdout; if you do, you need a new holdout.

### 2.4 Replications, confidence intervals, warm-up

- **Replications for ±x %:** run n₀ = 10 replications, compute s; then n = ⌈( t_{n₀−1,0.975} · s / h )²⌉ with h = 0.05·x̄ for ±5 %; iterate (Law & Kelton ch. 9 **[textbook]**; z-approximation n = (z·s/h)² ([Arizona spatial-sim paper](https://experts.arizona.edu/en/publications/generating-confidence-intervals-for-spatial-simulations-determini/)). Hoad, Robinson & Davies automate this (start with 3 reps, add until relative half-width ≤ 5 % and stays there for a look-ahead of k further reps **[recall of algorithm details]**) ([JORS 61(11):1632–1644, 2010](https://ideas.repec.org/a/pal/jorsoc/v61y2010i11d10.1057_jors.2009.121.html); [AutoSimOA](https://warwick.ac.uk/fac/soc/wbs/projects/autosimoa)). For a daily-cleared furniture line with CV ≈ 0.1 on daily output, ±5 % at 95 % needs ~16 reps; CV 0.2 → ~62 reps **[est.]**.
- **Terminating vs steady state:** if the plant starts each day/week with (near-)empty WIP, model it as a **terminating simulation** (one replication = one day/week, no warm-up). If WIP carries over for weeks (typical for batch furniture with 1–3-week lead times), treat lead time/WIP as steady-state outputs and remove initialization bias.
- **Welch's method:** n replications of length m; average across replications per time index; smooth with centered moving average of window w (2w+1 points); choose truncation l where the curve flattens; try several w ([Law & Kelton as summarized](https://www.informs-sim.org/wsc02papers/055.pdf); [GaTech thesis comparison](https://www.nctspm.gatech.edu/sites/default/files/u46/taylor_stephen_l_201012_mast_Analyzing%20methods%20of%20mitigating%20initialization%20bias%20in%20transportation%20simulation%20models.pdf)). **MSER-5:** batch output in 5s, choose truncation minimizing the half-width (MSE) of the remaining mean; Hoad & Robinson selected it as the best automatable method; fails if the optimum lies in the latter half of the run (run longer) ([Hoad & Robinson WSC 2011](https://wrap.warwick.ac.uk/43701); [Warwick warm-up method survey](https://warwick.ac.uk/fac/soc/wbs/projects/autosimoa/current_work/website_warmup_methods_total_doc.pdf)). Rule of thumb: run length ≥ 10× warm-up **[textbook]**; for this plant warm-up ≈ 2–3× mean order lead time **[est.]**.

### 2.5 Sensitivity / screening

- **Morris elementary effects:** r trajectories × (d+1) runs; r = 5–50; rank by μ* (mean |EE|) and σ (interactions). Extended to stochastic simulation with FDR control by Shen & Wan ([IJOC 2018](https://pubsonline.informs.org/doi/fpi/10.1287/ijoc.2018.0836); [Wikipedia EE](https://en.wikipedia.org/wiki/Elementary_effects_method); [WSC 2004 screening](https://www.informs-sim.org/wsc04papers/121.pdf)). For ~15 uncertain parameters (cycle-time means, CVs, MTBF/MTTR per machine, setup time, batch size, operator count), r = 10 → 160 runs.
- **OAT ±20 %** on each parameter as the first pass; report tornado chart of throughput and lead time. Parameters whose ±20 % change moves throughput < 1 % may stay at triangular/expert values; the rest must meet the sample-size standards of §1 and §6.

## 4. Trace-driven and record-driven modeling

- **Arrivals from order history vs fitted:** replay the trace when you must reproduce a historical period (validation); fit a **non-stationary (piecewise-constant) Poisson** or empirical daily-release distribution when you need to vary demand or test what-ifs. Piecewise-constant NSPP with weekday levels and input-uncertainty quantification ([WSC 2016](https://www.informs-sim.org/wsc16papers/033.pdf); [Leemis 1991 nonparametric NHPP](https://www.math.wm.edu/~leemis/1991mgmtsci.pdf); [Lancaster note](https://lancaster.ac.uk/~dangth/simulation.html)). For furniture, model *order release by the planner* (daily batch at planning run) rather than customer order arrival; keep product-mix and lot-size as empirical joint distribution from the records.
- **Process mining for routing**: minimum event log = case_id (order/lot), activity (station), timestamp; PM4Py has `rework` statistics (activities repeated within a case), `interval_lifecycle.to_interval` to pair start/complete transitions, and sojourn-time with business-hours calendar ([PM4Py rework](https://pm4py-source.readthedocs.io/en/latest/pm4py.statistics.rework.cases.log.html); [interval_lifecycle](https://pm4py-source.readthedocs.io/en/latest/_modules/pm4py/objects/log/util/interval_lifecycle.html); [sojourn_time](https://pm4py-source.readthedocs.io/en/latest/pm4py.statistics.sojourn_time.log.html)). Variants = distinct activity sequences; rework loop = variant containing a repeated station (e.g., edge bander → QC → edge bander). Time-synchronisation across MES/PLC clocks is a known pitfall ([Janke, Silesian Univ.](https://managementpapers.polsl.pl/wp-content/uploads/2025/02/212-Janke.pdf)). Celonis manufacturing cases: Eissmann (MES step logs → bottlenecks, adhesive time-limit scrap) ([TU/e PDF](https://www.win.tue.nl/ieeetfpm/casestudies/celonis_eissmann_-_success_story.pdf)); McKinsey/auto OEM rework hours ([McKinsey](https://www.mckinsey.com/capabilities/operations/technology-in-operations/celonis)).
- **Only end (or only start) timestamps**: (1) Wombacher heuristic — start = max(resource available, activity enabled); (2) Fracca, de Leoni et al. CAiSE 2022 — simulate candidate duration profiles and pick the one whose replay best matches the log ([arXiv 2208.12224](https://arxiv.org/pdf/2208.12224); [unipd PDF](https://www.math.unipd.it/~deleoni/documenti/F_dL_A_T@CAISE22.pdf)); (3) gamma latent wait/service decomposition from transition times ([US 10,733,526](https://patents.google.com/patent/US10733526)); (4) practitioner options when timestamps are missing ([Fluxicon](https://fluxicon.com/blog/2016/09/data-quality-problems-in-process-mining-and-what-to-do-about-them-part-9-missing-timestamps/)). In this project, the 2-week CT log gives *true* start/stop per machine; use it to calibrate the start-time repair on the ERP end-only records, then apply to 3–12 months.
- **Machine states from current**: a single feeder CT gives aggregate load; disaggregation is "inherently unidentifiable" when identical machines run concurrently ([SEDR-Seq2P, arXiv 2607.28693](https://arxiv.org/pdf/2607.28693)); textile case: aggregate energy fine, per-machine poor with simultaneous identical motors ([arXiv 2601.01616](https://web3.arxiv.org/pdf/2601.01616)); FHMM works on factory site data when machines have distinct state signatures ([JEPST 2024](https://dlkjxb.csust.edu.cn/dlgcjs/article/abstract/20240512)); public benchmark IMDELD: poultry-feed plant, 8 machines, 11 meters, 1 Hz ([IEEE DataPort](https://ieee-dataport.org/open-access/industrial-machines-dataset-electrical-load-disaggregation)). **Conclusion: use one CT clamp per machine** (beam saw, nesting CNC, edge bander, boring CNC, compressor/dust extractor) and reserve a feeder CT only for total energy. Per-machine state thresholds as % of rated current: off 0–5 %, idle 10–30 %, cutting 50–100 %, with 2–5 s debounce; calibrate from a known idle/air-cut/cut sequence on the visit day ([IMD knowledge base](https://industrialmonitordirect.com/blogs/knowledgebase/machine-uptime-monitoring-methods-for-manual-fabrication-equipment)). Edge banders are trickier: glue-pot heater and feed-chain motor run during idle, so detect *feed* via the trimming-motor channel or a camera/light-barrier count **[est.]**.

## 5. Observation bias on a one-day visit

- **Hawthorne / reactivity**: effect is short-lived and strongest on day one, so a single visit samples the most reactive period; mitigations — tell workers the purpose, observe many cycles and discard the first ones, hidden/unobtrusive timing cross-checked with worker logs ([WSC 2013 paper](https://informs-sim.org/wsc13papers/includes/files/240.pdf); [Velaction](https://www.velaction.com/hawthorne-effect/); [Statistics by Jim](https://statisticsbyjim.com/basics/hawthorne-effect/)). Office-occupancy surveys show first-day inflation corrected by randomized repeated samples plus system logs ([koji.so](https://www.koji.so/docs/hawthorne-effect-research)).
- **How auditors correct**: (1) pre-visit request of 12 months production, hours, utility bills; chart and check for trends before the visit (Industrial Assessment Center practice, [LSU IAC](https://iac.lsu.edu/process/)); (2) ask "how is today different?" — which products, which absentees, which machines down, any rush order, month-end; (3) compute the visit day's z-score against the 3–12-month daily output distribution and weight the day accordingly; (4) use the 2-week CT/camera log as the unbiased reference: the visit-day cycle times should fall inside the log's P25–P75 — if not, apply a rating correction (ILO performance rating) rather than discarding.
- **Rapid Plant Assessment (Goodson, "Read a Plant—Fast", HBR May 2002, R0205H)**: 11 categories scored 1/3/5/7/9/11 (Poor → Best in class) plus a 20-question yes/no questionnaire. Categories: 1 Customer satisfaction; 2 Safety, environment, cleanliness and order; 3 Visual management system; 4 Scheduling system; 5 Use of space, movement of materials and product-line flow; 6 Levels of inventory and WIP; 7 Teamwork and motivation; 8 Condition and maintenance of equipment and tools; 9 Management of complexity and variability; 10 Supply-chain integration; 11 Commitment to quality ([HBR store](https://store.hbr.org/product/read-a-plant-fast/R0205H); [MAAW summary](https://maaw.info/ArticleSummaries/ArtSumGoodson2002.htm); [The Auditor Online](https://www.theauditoronline.com/lean-rapid-plant-assessment-as-a-tool-for-more-effective-audits/); [WiSys how-to](https://www.wisys.com/how-to-do-a-rapid-plant-assessment/); [EisnerAmper PE use](https://www.eisneramper.com/insights/private-equity/rapid-plant-assessments-private-equity-due-diligence-1026/)). The 20 questions (visitors welcomed and informed; customer-satisfaction ratings posted; facility clean/safe; visual labeling of parts/tools/processes; schedule and metrics visible; flow and inventory discipline; team skills matrix; equipment maintained with records; complexity managed; supplier/customer integration; quality tools used) are **[recall — I could not retrieve the exact wording]**; categories 9 and 11 should be read as proxies for routing variability and rework rate in the model.

## 6. Evidence standard for this project (증거 기준표)

| Parameter class | Minimum sample / coverage | Primary data source | Distribution | Validation test | Tolerance (est.) |
|---|---|---|---|---|---|
| **Machine cycle time** (beam saw, nesting, edge bander, boring) | ≥ 30 cycles per part family from CT log (target n = (1.96·CV/0.05)²; CV 0.15 → 35); ≥ 10 timed on visit | CT clamp states (2 wks), CNC program times, visit stopwatch | Deterministic program time + lognormal noise; empirical tail | Visit-day mean inside log P25–P75; Q–Q of fit; sim vs log KS/AD | mean ±5 %, CV ±20 % |
| **Manual handling / assembly / packing** | GE table: 10–30-min tasks → 5–8 units; < 1 min elements → 30–60; else PMTS | Visit stopwatch + camera sampling + MOST/MTM-1 estimates | Lognormal (or gamma) with CV 0.2–0.35; triangular when n < 10 | Observed/PMTS ratio 0.9–1.3 per station; work-sampling activity split vs model (χ²) | mean ±10 % |
| **Setup / changeover** | ≥ 20 setups per machine from log-derived gaps; 3–5 timed live | ERP item-change sequence + CT gaps | Lognormal; frequency as setups/shift (Poisson or empirical) | Gap-method vs stopwatch within ±15 %; setups/day sim vs ERP | mean ±15 % |
| **Breakdowns (MTBF/MTTR)** | ≥ 10–15 failure events per machine for a fit (Weibull usable at 3–5 but low confidence; ≥ 20 preferred); if fewer, use availability (efficiency) approach | Maintenance log + CT "long idle during shift" episodes; interviews | TBF exponential/Weibull on **busy time**; repair lognormal/Erlang-2 | Availability sim vs log ±3 pp; down-episode count per month | availability ±3 pp |
| **Order arrival / release** | ≥ 3 months (≥ 60 working days) of order lines; 12 months if seasonal | ERP orders, planner release dates | Trace replay (validation); piecewise-constant NSPP by weekday + empirical mix/lot size (what-ifs) | Kleijnen trace-driven regression; weekly volume CI covers real | weekly output ±5 % |
| **Routing / rework** | All cases in 3–12 months; variant must appear ≥ 5× to be modeled; rework rate with ≥ 100 cases per station | MES/ERP event log via PM4Py | Empirical routing probabilities; rework Bernoulli per station | Discovered variants cover ≥ 95 % of cases; rework % sim vs log | rework rate ±2 pp |
| **Buffers / WIP** | ≥ 10 WIP snapshots (visit + camera stills twice daily for 2 wks) + ERP open-order WIP daily | Camera, ERP WIP report | Capacity as fixed constraint; initial WIP from records | Mean WIP and P90 lead time sim vs ERP; Turing test on WIP maps | WIP ±15 %, lead time ±10 % |
| **Worker allocation** | Skills matrix (all workers); shift/attendance 3 months; work sampling ≥ 271 obs (90 %, ±5 %) | HR roster, RPA team question, work sampling | Deterministic roster + empirical absence rate; task-time rating by skill | Utilization per worker sim vs sampling ±5 pp | ±5 pp |
| **Energy** | 2 weeks 1 Hz per-machine CT; monthly bills 12 months | Per-machine CT (not single feeder), utility bills | State-based power (off/idle/run) per machine | Sim kWh/day vs meter; monthly vs bill | ±10 % daily, ±5 % monthly |
| **Whole-model outputs** | n replications until 95 % CI half-width ≤ 5 % of mean (Hoad algorithm); warm-up by MSER-5/Welch if WIP carries over; Morris r=10 screening | — | — | Holdout period replay; paired t / Kleijnen regression; Schruben–Turing; extreme-condition tests; documented per VDI 3633-13 / Rabe-Wenzel procedure | throughput ±5 %, lead time ±10 %, utilization ±5 pp |

**Minimum-data verdict:** one observation day is sufficient only for face validity, rating calibration, and a handful of manual-element times; the 2-week per-machine CT/camera log is the evidence base for machine cycle, setup and energy; the 3–12-month records are the evidence base for arrivals, routing, rework, WIP and breakdown frequency; parameters that fail the sample thresholds above must be flagged "expert/triangular" in the assumptions document and shown to be non-influential by Morris screening before the model is accepted.
